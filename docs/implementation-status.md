The live readiness contract now declares `first_comparable_token=2` and
`warmup_excluded_tokens=[0,1]` for Dyna Gear; other sets retain token 1 as
their first comparable surface. The coordinator rejects an earlier requested
start before accepting any proof, so the exclusion is a pinned boot-boundary
normalization rather than permission to skip dynamic mismatches. Skipped
startup tokens now advance sequentially only after both producers publish the
same token and RTL publishes the authoritative next-frame input packet; they
are never pre-released with neutral input. Long proof runs omit full PPM files
for skipped startup tokens, retain the barrier/state/input evidence, and emit
only the requested raw comparison surface. The launcher's explicit gameplay
mode additionally requires the RTL frame-850 metric, a same-run Verilator PPM,
zero renderer overruns, and natural RTL gate exit before cleanup.

## Profile rule

Future work must update the shared descriptor/RTL path, this ledger, the
feature matrix, and the relevant focused test together. A change that only
works by selecting a different RBF or a compile-time game name is outside the
project contract.
